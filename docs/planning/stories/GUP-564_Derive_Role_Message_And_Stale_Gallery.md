# GUP-564: Derive Role Message and Stale Gallery

## Story Overview

**Initiative**: Strategic Review 2026-11 (N1 Docs and Tutorials) **Status**: 📋
Planned **Created**: 2026-10-26

## Context

Two small documentation faults found by GUP-531 (retrospective, "Follow-up
Stories").

**The derive's role message is out of date.** `#[derive(Mark)]` accepts
`role = X | Y | Size | Width | Height | Color`
(`crates/gup-core-macros/src/mark.rs` lines 154–156), but the error for any
other role says "`role` is one of `X`, `Y`, `Size` or `Color`" (line 159). No
compile-fail test covers an unknown role, which is how the message drifted.

**The gallery page lists examples that do not exist.** `docs/gallery/index.html`
is generated by `scripts/generate_gallery_html.sh` from
`scripts/gallery_config.toml`, which GUP-499 pruned to the five current
examples, but the committed HTML was never regenerated: it links 101 example
sources, 96 of them missing (`scripts/check_gallery_links.sh` reports "Checked
101 source links, 96 broken"), including `tutorial06_custom_marks` and the other
three `examples/tutorials/` entries. The link check runs only in the gallery CI
job (`mask ci gallery`), after regenerating, so it never sees the committed
file. Regenerating it (checked 2026-10-26) gives 5 examples and 0 broken links.

## User Story

> "As a developer writing a custom mark, I want the derive's error to list the
> roles it really accepts; as a visitor to the gallery, I want every card to
> link to code that exists."

## Acceptance Criteria

### AC1: The role message lists every accepted role

- [ ] The message reads exactly:
      `` `role` is one of `X`, `Y`, `Size`, `Width`, `Height` or `Color` ``.
- [ ] The accepted names and the message come from one `const ROLES: [&str; 6]`
      in `mark.rs` (the message is built from it), so they cannot drift again.
- [ ] New case `crates/gup-core/tests/derive_mark_fail/unknown_role.rs`
      (copyright header, a mark with `#[channel(role = Depth)]` on one field)
      and its `.stderr` from `TRYBUILD=overwrite`; the `.stderr` holds that one
      error and nothing else.
- [ ] `scripts/with_cargo_env.sh cargo test -p gup-core --test compile_fail -- --test-threads=1`
      passes.

### AC2: The gallery page is current

- [ ] Run `scripts/generate_gallery_html.sh` and commit the regenerated
      `docs/gallery/index.html`.
- [ ] `scripts/check_gallery_links.sh` ends with "0 broken".
- [ ] `rg -c tutorial0 docs/gallery/index.html` prints nothing (no match).

### AC3: The link check runs on every `all-check`

- [ ] In `maskfile.md`'s `all-check`, the `gallery` entry becomes
      `'./scripts/check_gallery_sync.sh && ./scripts/check_gallery_links.sh && ./scripts/check_story_ids.sh'`.
- [ ] `mask all-check` passes.

## Decisions

- Regenerate the HTML rather than hand-edit it: the script is the source of
  truth, and a hand edit would drift again.
- Run the link check in `all-check` (it reads one HTML file, well under a
  second), not in the pre-commit hook's file-filtered tasks.
- Thumbnails are not regenerated (that needs release builds of the examples and
  a GPU; CI does it). The page shows placeholders until CI runs.

## Escalation Triggers

- `TRYBUILD=overwrite` changes any `.stderr` other than the new one.
- The regenerated HTML lists an example whose source is missing.

## Out of Scope

- New gallery examples or thumbnails (CI's gallery job).
- Rewriting the gallery's styling.
