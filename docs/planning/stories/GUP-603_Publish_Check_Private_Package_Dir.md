# GUP-603: Publish Check Private Package Directory

## Story Overview

**Initiative**: Strategic Review 2026-11 (N3 Release 0.1) **Status**: ✅
Complete (2026-11-04) **Created**: 2026-11-04

## Context

On 2026-11-04 `mask publish-check` passed, then failed twice in the same
checkout with `no hash listed for gup-core-macros v0.1.0` (cargo's
`failed to verify package tarball`).
`cargo publish --workspace --dry-run --locked` passed with a private
`CARGO_BUILD_BUILD_DIR`, and CI passes. The cause is probably the shared
`$CARGO_BUILD_BUILD_DIR/package/tmp-registry` left by another checkout's dry run
of the same version with different contents. `mask release-check` must be
reliable on a machine with several checkouts.

## User Story

> "As the maintainer, I want the publish dry run to be reliable in a shared
> build directory, so that release day has no surprises."

## Decisions

- The publish step runs `cargo publish --workspace --dry-run --locked` with
  `CARGO_TARGET_DIR` set to a directory private to the run (a `mktemp -d` under
  the checkout's own target directory, removed on exit by a trap), so cargo's
  `package/` and `tmp-registry` are never shared. `CARGO_BUILD_BUILD_DIR` stays
  shared if that still works; if cargo puts `tmp-registry` under the build
  directory, that step uses a private build directory and the story records the
  cost.
- Proof: seed a stale `package/tmp-registry` in the shared location; show the
  old command fails and the new step passes.

## Acceptance Criteria

## Implementation Summary

- `scripts/publish_check.sh` (new) runs
  `cargo publish --workspace --dry-run --locked` with `CARGO_BUILD_BUILD_DIR`
  set to `$CARGO_TARGET_DIR/publish-check`, private to the checkout, and clears
  that directory's `package/tmp-registry` and `package/tmp-crate` first.
  `mask publish-check` runs it.
- Measured: cargo puts `package/` (the unpacked crates, the verification builds
  and `tmp-registry`) under the **build** directory and does not use the target
  directory for it, so a private `CARGO_TARGET_DIR` alone would not have helped;
  the private build directory is what isolates. Cost: the first run in a
  checkout is a cold build (469 s inside `mask release-check`, about 300 s
  alone); a second run took 54 s. The verification builds were never shared with
  `mask build` (they live under `package/`), so the only loss is sharing between
  checkouts.
- Test (`scripts/test_release_check.sh`, a fake `cargo` on PATH): the build
  directory handed to cargo is the private one, a seeded stale shared
  `package/tmp-registry` is untouched, a stale overlay in the private directory
  is cleared, and the arguments keep `--dry-run`.
- Not shown: the old command failing. The failure could not be reproduced by
  seeding: stale or cksum-less index entries and extra files are regenerated by
  cargo on the next run, and a second tree with the same version and different
  contents (run before, after and six times concurrently) passed in a shared
  build directory. The cause stays probable, not proven; the rule (no shared
  `package/`) removes the only state the checkouts shared.
- Evidence: the `publish` row of `mask release-check` passed twice in a row in
  one checkout (469 s cold, 54 s warm).

## Retrospective

**Completed**: 2026-11-04

### Key Technical Learnings

#### Where cargo keeps `package/`

- **Challenge**: The story and the orchestrator's decision assumed the private
  directory was the target directory.
- **Solution**: Measured it: with separate build and target directories, all of
  `package/` is under the build directory and the target directory stays empty.
- **Pattern**: Check which directory cargo uses before isolating it.

#### A failure that cannot be seeded

- **Challenge**: Seeds (stale index entries, no cksum, extra files, a differing
  tree, concurrent runs) all passed; cargo rebuilds the overlay index on every
  run.
- **Solution**: Tested the isolation property instead (a fake cargo records the
  directory it gets). The cause is recorded as not proven.
- **Pattern**: When the cause is unknown, a test of the rule is honest; a test
  that claims to reproduce the failure is not.

### Architectural Decisions

#### A persistent private directory, not a `mktemp` per run

- **Decision**: `$CARGO_TARGET_DIR/publish-check`, cleared of `tmp-registry` and
  `tmp-crate` on every run, instead of a fresh directory removed by a trap.
- **Reasoning**: A fresh directory costs a cold Bevy build (5 to 8 minutes) on
  every run; the persistent one is private to the checkout and runs in 54 s.
- **Trade-off**: A first run per checkout is cold; the directory counts against
  the checkout's target directory (removed with `mask clean`, pruned with the
  checkout).

### Development Workflow Insights

- The tooling guard in this environment refuses compound shell commands that
  mention paths built at run time; script files plus plain commands avoided it.
